Ardoise app map

A credit notebook for one shopkeeper and one phone. This page is a map of the code, not part of the app. It works with scripts disabled.

The pieces

  • Screen — src/App.tsx and src/components/. The slate, the sentence box, the correction sheet, the customer page.
  • Reader — parseEntry in src/lib/parseEntry.ts. Rules on the phone. No key.
  • Notebook — addEntry and balanceOf in src/lib/ledger.ts, saved by src/lib/storage.ts.
  • Reminder — reminderText and whatsappHref in src/lib/reminder.ts.

One action

The shopkeeper types a sentence and taps “Read the sentence”. The sheet shows what is still due. “Note it” stores the line.

Reference route

This route was prepared from the finished source. It was not walked live with a learner in the session that built the app.

  1. src/App.tsx — readSentence calls parseEntry and opens the sheet. saveDraft calls addEntry.
  2. src/lib/parseEntry.ts — parseEntry finds the customer, the items, the total, and the amount after “payé” or “paid”.
  3. src/lib/storage.ts — saveLedger writes the notebook. A reload calls loadLedger.

To change this, start here

  • The demo sentence is wrong — src/lib/parseEntry.test.ts, then parseEntry.
  • The balance is wrong — balanceOf in src/lib/ledger.ts.
  • The reminder sounds wrong — reminderText in src/lib/reminder.ts.
  • A label is wrong — src/lib/i18n.ts.

A practice to reuse

prd.md asked for a visible result: the sentence “Kofi a pris 2 sacs de riz 15000, payé 5000” shows 10 000 still due. src/lib/parseEntry.test.ts checks that result. A grouped amount, “15,000”, first came back as 15. The test failed on the number, which showed that a comma was being treated as a break between items. On another project, write the one screen result you care about as a check before polishing the interface.

How to run it again

npm install, then npm test, then npm run dev. This map is a snapshot of the source and can drift after later edits.
